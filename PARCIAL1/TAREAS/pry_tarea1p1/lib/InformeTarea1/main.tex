% ═══════════════ 1. INTRODUCCIÓN ═══════════════
\section{Introducción}

El presente informe documenta el desarrollo de la \textbf{Tarea 1} de la asignatura de Desarrollo de Aplicaciones Móviles. Se implementaron cinco ejercicios de lógica y cálculo dentro de una aplicación Flutter, utilizando el patrón arquitectónico \textbf{MVC (Modelo--Vista--Controlador)} y el paradigma de diseño \textbf{Atomic Design} para la construcción de la interfaz de usuario.

La aplicación cuenta con un \textbf{menú lateral (Drawer)} que permite navegar entre los cinco ejercicios. Cada ejercicio incluye validaciones de entrada, cálculos correctos y presentación clara de resultados.

% ═══════════════ 2. OBJETIVOS ═══════════════
\section{Objetivos}

\subsection{Objetivo General}
Desarrollar una aplicación móvil en Flutter que implemente cinco ejercicios de lógica y cálculo, aplicando el patrón arquitectónico MVC, el paradigma Atomic Design y navegación mediante menú lateral (Drawer).

\subsection{Objetivos Específicos}
\begin{itemize}[label=\small\color{verdeO}$\blacksquare$]
    \item Aplicar el patrón MVC separando la lógica de negocio, validaciones e interfaz gráfica.
    \item Implementar Atomic Design para crear componentes reutilizables (átomos, moléculas, organismos).
    \item Desarrollar los ejercicios 5, 6, 8, 9 y 10 con validaciones completas de entrada.
    \item Implementar navegación mediante Drawer y Navigator entre pantallas.
    \item Diseñar una interfaz de usuario clara, funcional y coherente en colores.
\end{itemize}

% ═══════════════ 3. MARCO TEÓRICO ═══════════════
\section{Marco Teórico}

\textbf{Flutter} es un framework de código abierto desarrollado por Google para crear aplicaciones multiplataforma desde una sola base de código en el lenguaje Dart.

\textbf{Patrón MVC (Modelo--Vista--Controlador):} Arquitectura de software que separa una aplicación en tres componentes: el \textit{Modelo} gestiona los datos y la lógica de negocio; la \textit{Vista} presenta la interfaz de usuario; y el \textit{Controlador} actúa como intermediario, validando las entradas y coordinando la comunicación entre Modelo y Vista.

\textbf{Atomic Design:} Metodología propuesta por Brad Frost que estructura las interfaces en cinco niveles jerárquicos: \textit{Átomos} (elementos básicos como botones y campos de texto), \textit{Moléculas} (combinaciones de átomos), \textit{Organismos} (secciones complejas), \textit{Templates} y \textit{Páginas}.

\textbf{Drawer (Menú Lateral):} Componente de Material Design que proporciona un panel de navegación deslizable desde el borde de la pantalla. En Flutter se implementa mediante el widget \texttt{Drawer} dentro de un \texttt{Scaffold}.

\textbf{Validación de Datos:} Proceso de verificación de entradas del usuario para garantizar la integridad de los datos antes de procesarlos. Incluye verificación de campos vacíos, tipos de datos incorrectos y rangos inválidos.

\subsection{Ejercicio 5: Conversor de Unidades de Longitud}
Se ingresa una medida en metros y se convierte a yardas, pies, centímetros y pulgadas.

\subsubsection{Modelo}
\begin{tcolorbox}[title=ConversionLongitudModel]

void convertir(double valorMetros) {
  metros = valorMetros;
  centimetros = metros * 100;
  pulgadas = centimetros / 2.54;
  pies = pulgadas / 12;
  yardas = pies / 3;
}
\end{lstlisting}
\end{tcolorbox}

\subsubsection{Controlador}
\begin{tcolorbox}[title=Validaciones Ejercicio 5]
\begin{lstlisting}
String validarMetros(String texto) {
  if (texto.isEmpty) return 'Error: Ingrese un valor.';
  double? valor = double.tryParse(texto);
  if (valor == null) return 'Error: Numero invalido.';
  if (valor < 0) return 'Error: Debe ser >= 0.';
  return '';
}
\end{lstlisting}

\subsection{Ejercicio 9: Producción Semanal del Operario}
Registra producción de lunes a sábado. Si el promedio $\geq$ 100 unidades, el operario recibe incentivos.

\subsubsection{Modelo}
\begin{tcolorbox}[title=ProduccionSemanalModel]
\begin{lstlisting}
void calcular(List<int> valores) {
  produccionDiaria = List.from(valores);
  totalUnidades = produccionDiaria.fold(
      0, (sum, val) => sum + val);
  promedio = totalUnidades / produccionDiaria.length;
  recibeIncentivo = promedio >= 100;
}
\end{lstlisting}
\end{tcolorbox}

% ─── NAVEGACIÓN ───
\subsection{Navegación entre Pantallas}

La navegación se implementa mediante dos mecanismos:
\begin{itemize}
    \item \textbf{Drawer:} Menú lateral accesible desde el icono de hamburguesa en el AppBar. Cada opción utiliza \texttt{Navigator.push()} para navegar a la página del ejercicio correspondiente.
    \item \textbf{Tarjetas de acceso rápido:} En la pantalla principal, cada tarjeta es un \texttt{InkWell} que navega directamente al ejercicio seleccionado.
\end{itemize}

\begin{tcolorbox}[title=Código de Navegación]
\begin{lstlisting}
// Desde el Drawer
onTap: () {
  Navigator.pop(context); // Cierra drawer
  Navigator.push(context,
    MaterialPageRoute(builder: (_) => page));
}
\end{lstlisting}
\end{tcolorbox}

\section{Conclusiones}
\begin{itemize}[label=\small\color{verdeO}$\blacksquare$]
    \item El patrón \textbf{MVC} permitió una separación clara entre la lógica de negocio, las validaciones y la interfaz, facilitando el mantenimiento y la escalabilidad del código.
    \item El uso de \textbf{Atomic Design} demostró ser una metodología eficaz para la construcción de interfaces modulares y reutilizables en Flutter.
    \item Las \textbf{validaciones} en el controlador garantizan la integridad de los datos, previniendo errores como campos vacíos, valores no numéricos y valores negativos.
    \item La navegación mediante \textbf{Drawer} proporciona una experiencia de usuario intuitiva y organizada.
    \item Cada ejercicio fue implementado siguiendo los requerimientos exactos del enunciado, con resultados verificados.
\end{itemize}

% ═══════════════ 6. RECOMENDACIONES ═══════════════
\section{Recomendaciones}
\begin{itemize}[label=\small\color{verdeO}$\blacksquare$]
    \item Adoptar el patrón MVC desde el inicio de cada proyecto para mantener un código organizado y escalable.
    \item Implementar pruebas unitarias para cada modelo y controlador, asegurando la confiabilidad de los cálculos.
    \item Utilizar Atomic Design de forma consistente para facilitar la reutilización de componentes en proyectos futuros.
    \item Considerar el uso de gestores de estado como \texttt{Provider} o \texttt{Riverpod} en aplicaciones de mayor complejidad.
    \item Realizar pruebas en múltiples dispositivos y resoluciones para garantizar la responsividad de la interfaz.
\end{itemize}
